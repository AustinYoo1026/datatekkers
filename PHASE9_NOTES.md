## 9.2 Challenges (local only)
- `js/challenges.js` (pure) `ISO.Challenges`: three dailies (tally, match or drill, hard match) and three weeklies, drawn from the local calendar date (`dayIdx`, Monday-start `weekIdx`), identical on every device, never yesterday's three (drawn sequentially from a fixed epoch day). Rewards: dailies 60/100/160, all three +80, streak bonus 20 x min(6, streak-1) once a day; weeklies 250/400/550. Ceilings 520 per day and 4,840 per week (`ceiling()`, `WEEK_CAP` 5,000). Credits only, auto-paid on finish.
- Counts: CPU, MyCareer or cup at Normal or harder; never online, Testing Arena, custom drills or Easy. Own tracker `App.chTr` (independent of the career objectives).
- Honest limits: the date is the device clock. A FORWARD clock change cannot be detected locally and earns at most 520 cr per simulated day (the streak resets on a jump). A BACKWARD change voids today and the week and zeroes the streak; a day that already paid comes back void if the clock returns to it. A corrupt saved day becomes a void day, never a fresh one. The profile is editable localStorage anyway; online matches pay nothing. "Leaderboards" are local personal bests (best streak, total done).
- UI: `js/challenges-ui.js`, overlay `#chal` (CHALLENGES button on the menu, strip in PLAY), end-screen rows and toasts, a list in the pause menu.

## 9.4 Performance
- `tools/bench.js` + `tools/bench-baseline.json` (CI). Timings (informational, never fail): sim step, AI update, a Predictor rewind (MAXPRED steps of `Game.step`, an upper-bound proxy: the real Predictor also copies state), anim3d per actor, stadium build per map. BLOCKING: profile bytes after `Profile.maxAll()` (15,212 B against the 64 KB budget), challenge state (572 B, budget 4 KB), and per map at quality 0 and 2 draw calls and triangles (not above the baseline). `--update` rewrites the baseline.
- Budgets at 60 Hz (documented targets): sim <= 1 ms per step (measured ~0.006 ms), 2D draw <= 6 ms, 3D CPU <= 5 ms (the last two are browser only: Debug HUD PERF section).
- `tools/dispose-test.js` (CI): proxies every THREE geometry / material / texture constructor and `dispose()`; stadium (20 maps x q0/q2), 12 players + `clearCache`, ball, three rounds each: created - disposed = 0. Leaks found and fixed: `player3d.js part()` never disposed its source geometry (one per head part per player) and `clearCache()` did not free the hair-lock geometries hung off the head's `userData.locks`. The stadium and ball were clean.
- `R3D.adaptTier` (js/3d/r3d.js): downgrades still use the frame INTERVAL (> 19 ms for 2 s); upgrades use measured WORK time (`performance.now()` around `renderInner`, average < 7 ms for `upWait` seconds, 10 s to begin); `upWait` doubles (cap 160 s) every time a tier we just climbed to (within 40 s) has to be left again. `settings.quality`: `auto` adapts; `low / med / high` = tier 2 / 1 / 0, fixed, no adapting (the select already had these values; its note text changed). Start tier: `settings.lastTier` (new flat key, default null, written on each auto switch), else a device hint (hardwareConcurrency <= 4 or deviceMemory <= 4 -> 1, a software renderer string -> 2). `R3D.debug()` also reports `workAvg`, `upWait`, `fixed`. NOTE: CPU time around `renderInner` does not see GPU time (WebGL is asynchronous); a GPU-bound device is only caught by the interval downgrade. That is why the 7 ms bar is conservative.
- Caps: 2D `fx.parts` at 400 (`PART_MAX`), rain segments 1800 -> 900 at tier 2 (applied on tier change too), LRU of 24 sheets on `Sprites` `cache` (a match uses about 14) and 160 portraits, `fx.dispose()` on a renderer rebuild in `ensure()` (the camera has no GPU resources), the menu demo is drawn every other frame (30 fps, dt carried over), slider saves debounced 300 ms in meta-ui.js (`setAccSlide`), `Profile.onSaveFail(cb)` fires once if localStorage refuses a write (main.js shows a toast; behaviour otherwise unchanged), `Profile.bytes()`.
- Lazy loading of 3D modules: not done. three.min.js is already lazy; the module parse cost was not measured in a browser, so there is no evidence it matters. Skipped on purpose.
- Mobile / touch: BLOCKED (there is no touch input). Nothing was done.
